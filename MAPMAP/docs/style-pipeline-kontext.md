# Kontext style-pipeline backend

The existing style pipeline remains responsible for target routing, tile composition,
postprocessing, QA, and asset application. `style_backend.py` keeps the old
`style_transfer_image` call contract and delegates model inference to
`kontext_client.py`.

Kontext-specific rules:

- `FLUX_KONTEXT_STEPS` defaults to `24`.
- `FLUX_KONTEXT_SEED` defaults to `42` and is passed to a CPU generator.
- `FLUX_KONTEXT_LORA_PATH` defaults to the provided sibling `Flux-training` LoRA.
- `FLUX_KONTEXT_LORA_SCALE=0.0` is the no-LoRA control and `1.0` is the enabled
  control. Both conditions use the same seed.
- The prompt cap is `300` characters. When truncation is necessary, concept text
  is removed from the front so the style tail and trigger remain available.
- The adapter injects `gdtpix` once at the beginning of the prompt. The SDXL
  baseline does not contain this token.
- `strength` is an edit-intensity tier (`Subtle`, `Balanced`, or `Strong`), not
  denoising strength. The UI label is `edit intensity`.
- `tile_stylize.py` owns integer NEAREST work-size preparation. The Kontext client
  does not pixel-art upscale, max-side resize, or palette quantisation.
- On CUDA, NF4 quantisation and CPU offload are enabled by default for the 12B
  model. Set `FLUX_KONTEXT_QUANTIZE=false` to request full precision on a larger GPU.
- Alpha restoration uses NEAREST for any mask-size adjustment. Palette snapping
  remains in the existing deterministic postprocess path.
- Because Kontext has no txt2img mode in this service, anchors are generated by
  editing four fixed repository source images with fixed seeds. Generating new
  anchors resets the approval gate.

Evaluate the baseline and migrated output with content-fidelity composite, edge,
and luma values separately. The current `tree_1` SDXL signature is approximately
`0.53` composite, `0.28` edge, and `0.78` luma. Low edge and low luma together
indicate likely content replacement.
